# Web interface: lists that scale

Objective: make the runs list, the branches and the changed files of `knit ui` usable with many items: compact rows, pagination, a text filter, detail on demand. Branch: `feat/scalable-lists`. Delivery: sequential, inline; commits per work unit, no AI attribution. Test runner: vitest (`pnpm test`), plus `pnpm typecheck` and `pnpm build`.

## Specs

- **S1. Runs.** "el orquestador, tiene bloques o tarjetas demasiado grandes de las RUN y sin paginación, ten en cuenta que en un proyecto pueden llegar a haber muchas". Runs become compact one-line rows, paginated, with a text filter and a status filter.
- **S2. Branches.** "lo mismo de las ramas". Each branch is one compact row (task, branch, state chips); its commits and actions open on demand; paginated with a text filter.
- **S3. Changed files.** "en el modal de Cursor, sus bloques dentro del modal como los cambios, las ramas, es demasiado grande y poco escalable visualmente". Changes are grouped by task, collapsed by default with file and line counts; paginated.
- **S5. Cursor modal, no Files tab.** "Eliminaría totalmente el apartado de files del modal de Cursor, creo que no aportaría nada teniendo la visual de changes de una tarea." (replaces S3's Files tab: the changes of a task stay in its detail).
- **S6. Cursor Agent tab compact.** "En el primero tab de agentes, no sé si es la tarjeta de Latest la que se ve así de grande o todas, pero debería ser mucho más comprimida y desplegable o expandida en su lugar."
- **S7. Branch row.** "en vez de mostrar la rama creada y trabajada abajo, la colocaría en donde va el título actual de la tarea, con su icono, ya que este es el apartado de ramas. Abajito en el apartado de detalles expandibles, mantendría sus tres etiquetas y los commits." The expanded view is smaller still. Remove the note "Pull requests go into ... Nothing is pushed until you press the button."
- **S8. Pull request target.** "permitiría que al levantar la PR se elija hacia donde se quiere levantar, por defecto, con la opción recomendada por el orquestador o claude dependiendo de si depende de una tarea o no." Default: the base the rules already compute (the branch of the task it depends on, else the run's base).
- **S9. Claude session title.** "en el modal de Claude, se sigue viendo el nombre de la sesión actual antigua sin el título que se modificó, en mi caso se ve /usage en lugar del nombre "prueba cursor" que le puse."
- **S10. Orchestrator modal.** "no me terminó de convencer su tono café claro, se ve raro, y no me gusta su formato tan moderno con tanto hover y sombras, lo mostraría más minimalista y a lo mejor volviendo al tono anterior de blanco y medio verdoso, ya no café. Las tarjetas de tareas acá igualmente deberían ser mucho más comprimidas. Los detalles del desplegable me parecen bien. También, re-implementaría la visual en general del apartado de tareas y run, como que se viera que una run o runs dependen de una tarea, ahora parecen eventos independientes sin conexión. [...] las tarjetas se ven demasiada cargadas de hover y sombras en general, no me gusta. Sobre todo ese borde en las tarjetas de runs." Assumption: runs and tasks must read as one hierarchy (the selected run holds its tasks, nested under it), not as two unrelated columns.
- **S11. Description without tokens.** "Podríamos armar estructuras predeterminadas por medio del orquestador para el cuerpo de las PRs y que Cursor no tenga que estar haciendo esto por medio de tokens, ya que sería un desperdicio aunque sea un modelo pequeño." Confirmed: "Sí, haz este último cambio para despues probar."
- **S12. Dropdown and hierarchy.** "en vez de escribir manualmente las ramas de las PRs [...] deberia salir un desplegable con todas las ramas disponibles [...] Actualizadas." and "la jerarquía en las tareas desplegables de Cursor siguen igual, no se ve como dentro del desplegable como si fueran parte y el texto de resumen no se ve apegado el título y se ve igual de grande. El de orquestador se ve bien, pero sigue habiendo demasiada separación entre el texto resumen de la tarea y el título." Note: the list is origin's branches, not `git branch` (local), because GitHub needs the base on origin.
- **S13. Pull request state and body.** "no me gusta el texto o aviso 'Opened …' basta con la etiqueta"; "veo innecesario el apartado de cambios en el cuerpo de la PR, lo quitaría"; "debería salir que fue mergeada con el mismo estilo de GitHub, en morado [...] de que permita saberse de alguna manera a que rama se mergeó."
- **S14. Blocks and numbers.** "los estados de los bloques, ¿Qué aportan realmente el estado de Done? [...] mejor mostrar sus modelos." "la barra verde [...] yo la quitaría" "al dejar el mouse encima en tokens o attempts, mostraría una pequeña descripción." "el uso [de Claude] muestra un uso anterior no actualizado." "Pull request ↗ a pesar de ya estar mergeado." "el apartado de cambios [...] se ve mal y como solapado."
- **S4. Overall.** "necesito full flexibilidad y visibilidad clara, solo lo que me interesa, no ruido visual." Nothing new is shown by default beyond what identifies and states each item.
