# Web interface: polish and identity

Objective: polish the single view of `knit ui`: blocks with their own identity (not phone-shaped), an inline quick-access expansion per block, a modal instead of the side panel, prompt routing to the orchestrator, and a Cursor view that shows reasoning and changes live. Branch base: `docs/single-view-close` (tip of the stack). Delivery: sequential, inline, no parallel agents (user: "Vamos de a poco sin levantar agentes en paralelo para optimizar los tokens"); one branch per task, stacked PRs, no AI attribution. Test runner: vitest (`pnpm test`), plus `pnpm typecheck` and `pnpm build`.

## Specs

- **S1. Block shape.** "No me gusta la visual de los bloques, parecen celulares con el formato actual." "Me gusta la estructura de bloques y su conexión visual, mantendría esto como esturctura base." Keep three blocks joined by wires; change their shape so they no longer look like phones.
- **S2. Orchestrator name.** "El orquestador no se llama Knit, Knit es el nombre en general de nuestro proyecto, pero el orquestador es simplemente un orquestador." The middle block and its panel are labeled Orchestrator; Knit stays the product name.
- **S3. Inline quick access.** "El texto clickeable de ver más detalles dentro de un bloque, debería expandirlo y mostrar los detalles extra hacia abjo en el modelo, ya sea Claude o Cursor, aquí dando como un acceso rápido sin necesidad de entrar al bloque. En donde se permita cambiar de modelo, presionar para ver los agentes activos si es que hay, ver el espacio de contecto y demás."
- **S4. Modal instead of side panel.** "Si se presiona una caja, quiero que se abra como una animación o modal en lugar de expandirse al lado derecho como lo hago ahora. Este quedaría sobre la vista principal, aquí se desplegarían todas las funcionalidades del modelo, como si fuera una extensión o pluging de Visual Studio o el mismo Claude dentro de Cursor como ahora. Debo poder cambiar de sesion, cambiar de modelo, etc."
- **S5. Prompt routed to the orchestrator.** "Con un switchs o algo mejor, de poder elegir que el prompt que le coloque vaya al orquestador y gatille algún plan definido dentro de odd/tasks, por ejemplo, de modo que gatille el desarrollo de Cursor y comience el monitoreo o trabajo, por decirlo de alguna forma." Decision (L3): with the switch on, the prompt goes to Claude asking for a plan in the Knit plan format; Knit validates it, the user confirms with one click, and the run starts with Cursor. Reuses plan detection and "Send plan to Knit".
- **S6. Cursor view.** "En cuanto a Cursor, lo mismo al presionar para desplegar detalle o presionar su bloque, debería dejarme escribir prompts, etc., con la diferencia, de que como este será más las manos, debería estar viendo su razonamiento y cambios dentro de la sesión, como si estuviera dentro de Cursor normalmente, ¿Se entiende? Todo esto lo podemos aprovechar de CLI."
- **S7. Orchestrator as a pipeline.** "En cuanto al orquestador, me lo imagino como un pipeline, similar a la estructura que tiene ahora."
- **S8. Identity.** "El bloque de Cursor debe de tener su propia identidad, es decir, tener una interfaz y margen de estilo de Claude Code, con el mismo icono y a lo mejor para hacerlo más bonito, encima de su bloque el típico monito naranja. El que aparece en la consola de WSL. Similar para Cursor, ya de por si el mismo bloque debe tener como su identidad." Read as: the Claude block takes Claude Code's style and icon with the orange terminal mascot above it (the sentence names Cursor first, then "Similar para Cursor"); the Cursor block gets its own identity.
- **S9. Overall.** "En general, quiero que toda la interfaz web sea mucho más bonita, con mayor identidad, didactiva y organizada, aprovechando todas las herramientas que tenemos."
