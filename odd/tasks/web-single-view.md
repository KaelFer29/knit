# Web interface: single interactive view

Objective: replace the page-per-view layout of `knit ui` with one interactive view (Claude, Knit, Cursor blocks joined by a pipeline of wires, each block opening a side panel), rebuild the configuration preview, and fix the `/usage` and undo defects. Branch base: `fix/review-advisories` (tip of the web-interface stack). Delivery: one branch per task, stacked PRs, no AI attribution. Test runner: vitest (`pnpm test`), plus `pnpm typecheck` and `pnpm build`.

## Specs

- **S1. One view.** User: "no me gusta mucho su estructuración por vistas. Creo que te basaste mucho en el proyecto de Vibe Kanban. Yo me lo imagino más como todo en una sola vista interactiva con desplegables ordenados." The first screen is the whole product; there are no Runs / Workspace pages to switch between. The runs list, sessions list and file explorer move inside the panels (S3 to S5).
- **S2. Three blocks and the pipeline.** User: "que automaticamente en la primera vista que se abre, pueda visualizar por así decirlo tres bloques, al lado izquierdo Claude, como una caja con el estilo de claude, que represente el cerebro y el inicio de las ejecuciones. Donde en este bloque se vayan viendo de por sí todas las acciones realizadas por Claude en este momento y su estado actual." and "Al medio, estaría el bloque del orquestador con la misma lógica, y al lado derecho, Cursor con practicamente los mismos detalles que el bloque de claude." and "Esto me lo imagino como con conexiones visuales muy lindas, aprovechando al máximo el diseño de frontend con las tecnologías actuales, como que se muestre un cableado que visualmuestre la etapa en la que se va en cada cosa, que se muestren mini logs sobre este cableado de lo que se está enviando, etc. Algo como inspirado en una visual de canalización de CodePipeline." Each block shows its live state and latest actions without being opened, in its agent's brand style (identity module). The wires show the current stage of each hop (plan sent, task queued, prompt sent, result back, verdict) and short live log lines of what travels on them. Every animation honors `prefers-reduced-motion`.
- **S3. Claude panel.** User: "Al presionarlo, que se habra un detalle de practicamente un detalle mucho más especifico, su modelos, sus agentes actuales, etc, como si fuera este panel de extensión dentro de Cursor. Con las mismas funcionalidades que tenemos acá, dentro de las posibles. Y aquí que pueda enviar mensajes y poder gatillar yo cuando comenzar con las instrucciones o promtps al orquestador para que vaya a Cursor." Decision (L3): the detail opens as a side panel; the pipeline stays visible and animated behind it. The Claude panel holds sessions and switching, model and profile, chat with command palette and usage, the detected plan with its validation, and an explicit control to send the plan to Knit. A Claude turn never starts a run by itself.
- **S4. Knit panel.** "con la misma lógica": runs list and picker, task queue, checks and verdicts, run control (start, abort, resume, retry), in the same side panel.
- **S5. Cursor panel.** "practicamente los mismos detalles que el bloque de claude": tasks, attempts, agent timeline, diff, files touched and worktree changes, the file explorer, model, in the same side panel.
- **S6. Configuration preview.** User: "Me agrada la vista de configuraciones, esto lo veo necesario como una vista previa, pero reimplementaría toda la visual." Configuration opens from the single view as a preview over it (not a separate page), with the visual rebuilt; the allow-list, diff before save, backups and conflict handling stay as they are.
- **S7. `/usage` does nothing.** User: "Escribo un comando como /usage y no pasa nada, no me envia nada en la sesión de Claude." Evidence (L2): the command only opened the usage panel, which is open by default. Fix: `/usage` is sent to the agent's session as a turn and its answer is shown; for an agent that does not report plan usage, the interface says so instead of doing nothing.
- **S8. Undo in the editor.** User: "Al modificar archivos, tampoco puedo usar ctrl z, no cumple con los criterios básicos de accesibilidad." Evidence (L2): in Chromium each Ctrl+Z undid one character, and the history was lost when switching to the review step (the field remounts). Fix: an editor with real undo and redo history kept across edit and review, full keyboard use and accessible labels.
